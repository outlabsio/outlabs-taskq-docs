# Fencing and settles

Every claim creates a server-generated `attempt_id`. Heartbeat, complete, fail, release, and snooze CAS on `(job_id, attempt_id)`.

## Settle results

| Result | Meaning |
|---|---|
| `ok` | Transition applied |
| `already_settled` | This attempt already finished — treat as success on retry |
| `lost` | Fence lost (another attempt owns the job) |
| `retry_scheduled` | Failure accepted; job re-queued with backoff |
| `dead` | Terminal failure |

A dropped HTTP response after a successful settle is no longer indistinguishable from theft: retrying complete returns `already_settled`.

## Handler return values

Handlers return typed results; the worker maps them to SQL:

| Return | SQL | Burns attempts? |
|---|---|---|
| `Complete` | `complete_job` | no |
| `Snooze` | `snooze_job` | **no** |
| `Cancel` | cancel path | no |
| `Retry` | `fail_job(retryable=true)` | yes |
| `NonRetryable` | `fail_job(retryable=false)` | terminal |
