Entry points from `outlabs-taskq`:

| Command | Purpose |
|---|---|
| `taskq migrate <dsn>` | Apply packaged migrations under an advisory lock |
| `taskq verify <dsn>` | Read-only manifest drift check |
| `taskq worker …` | Run a DB-direct or HTTP worker |
| `taskq auth sync-permissions …` | Report/apply OutLabs IAM rows (`[outlabs]` required) |
| `taskq-bench run <scenario> --dsn …` | Report-only benchmarks |

## Worker

Configure exactly one transport: `--dsn` **or** `--http-base-url`.

```bash
taskq worker \
  --dsn "$DATABASE_URL" \
  --registry myapp.tasks:registry \
  --queue mail \
  --queue courts \
  --environment development \
  --concurrency 4 \
  --batch 2
```

HTTP workers (no DB credentials):

```bash
taskq worker \
  --http-base-url https://api.example.com/taskq \
  --registry myapp.tasks:registry \
  --queue mail \
  --environment staging \
  --http-bearer-token "$TOKEN" \
  --no-listen
```

Most knobs also load from `TASKQ_*` environment variables via `WorkerSettings`. See [Configuration](/reference/configuration).

::note
HTTP workers cannot use PostgreSQL `LISTEN`. Production requires `--allow-production` (or `TASKQ_ALLOW_PRODUCTION=true`) when `--environment production`.
::

## Auth provisioning

```bash
taskq auth sync-permissions \
  --dsn "$AUTH_DATABASE_URL" \
  --queues mail,exports \
  --apply
```

`--queues` is one comma-separated list. Omit `--apply` for a dry-run report;
add `--reconcile` only when the command should also reconcile existing rows.
