# Introduction

**OutlabsTaskq** (`outlabs-taskq`) is a Postgres-native task queue for Python fleets.

It is infrastructure we extracted from production systems at OutLabs — the same class of problem as `outlabs-auth`: stop reinventing a foundational backend piece in every product.

## Why it exists

Most teams either:

1. Run Redis / RabbitMQ / Celery and accept another operational dependency, or
2. Grow an ad-hoc `jobs` table until claim races, lost settles, and silent duplicates show up at 2am.

OutlabsTaskq takes a third path: **PostgreSQL is the broker**, and the **PL/pgSQL functions are the contract**. The Python package is a typed client — not a second source of truth.

## What you get

- Claim with `FOR UPDATE SKIP LOCKED`
- Attempt fencing (`current_attempt_id`) so stale workers cannot settle stolen work
- Typed settle results (`ok`, `already_settled`, `lost`, …)
- Idempotent enqueue with named uniqueness modes
- Concurrency limits stamped per job
- Optional FastAPI HTTP facade for workers that must not hold DB credentials
- Optional `outlabs-auth` adapter for facade auth — **not required** by the engine

## Status

Pre-alpha. The protocol and product surface are documented; the publishable package is under active extraction. These docs track the intended public API as it lands.
