# Enqueue

Every enqueue returns a structured `EnqueueResult`. Never infer success from a missing id.

## Statuses

| Status | Meaning |
|---|---|
| `created` | New row inserted |
| `existed` | Active key already present (reject mode) |
| `replaced` | Unlocked active row overwritten |
| `skipped_locked` | Active row is `running`; replace refused |
| `conflict` | Semantic conflict without a safe row to point at |

## Uniqueness modes

| Mode | Behavior |
|---|---|
| `reject` (default) | Conflict → `existed` |
| `replace` | Overwrite unlocked job (debounce / reschedule) |
| `preserve_run_at` | Replace payload; keep schedule for never-started jobs |

`concurrency_key` is separate: it caps parallel runners, it is not an enqueue identity key.

## Bulk

`enqueue_many` returns one result per input item in order.
