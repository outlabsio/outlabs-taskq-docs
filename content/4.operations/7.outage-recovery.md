Package **0.1.0a42** keeps SQL contract **0.6.12**, Protocol **1.0.18**, and
migrations **0001–0048**. It changes worker and HTTP-facade recovery, with no
database migration from a40/a41. Upgrade the API and workers independently,
in either order; each change gives its own protection.

## What changes

| Component | a42 behavior |
| --- | --- |
| Worker heartbeat | Ownership is lost after no confirmed heartbeat for `lease - min(60, lease / 4)`, measured from the last confirmed heartbeat send (the claim request send initially). Fast repeated connection failures no longer exhaust ownership in three attempts. |
| Heartbeat task | Each heartbeat is bounded by its remaining budget. A crashed or cancelled heartbeat task drops ownership. |
| Owned settlement | Transient `TQ503`, server `TQ500`, and transport failures can retry past `settle_max_attempts` while heartbeats stay healthy, bounded by one lease budget. A draining worker retains the attempt cap. |
| Protocol errors | `TaskqProtocolError` remains a `TaskqInternalError` subclass (`TQ500`), but malformed replies retain the settle-attempt cap. Retrying cannot repair a malformed envelope. |
| HTTP claim delivery | The facade releases claims when the client has disconnected or the delivery window has expired: more than `max(28 seconds, wait_seconds + 3 seconds)` since handler start. It returns `TQ503 claim_undeliverable`. Release is fenced and consumes no retry budget. |

## Choose an HTTP lease

With the default 30-second HTTP request timeout, use a lease of at least about
**75 seconds**. Very short leases can lose ownership during a slow but
successful heartbeat. Lowering claim wait (for example to 10 seconds) can
leave more margin for a claim response. Check the host's own proxy, database,
and request timeouts rather than changing a single setting in isolation.

## Diagnose recovery

Observe events by `job_id` and `attempt_id`:

- `job.heartbeat_failing` / `job.heartbeat_recovered`;
- `job.settle_failing` / `job.settle_recovered` / `job.settle_exhausted`;
- `job.ownership_lost` (warning);
- `claim.undeliverable` on the facade.

Use the [CLI](/getting-started/cli) to inspect job state and events. Lease
expiry remains the recovery path when a claim cannot be safely released.

## Remaining limits

A response lost after the facade's delivery check can still orphan a committed
claim until lease expiry. Time spent before handler entry (such as host auth
or database-pool waits) is outside the delivery-window measurement. In-flight
settle calls are not themselves bounded by the lease budget, and a synchronous
or cancellation-ignoring handler may keep running after ownership is lost.
Permanent server-side `TQ500` errors may be retried for one lease budget;
release does not refund GCRA tokens or restore a half-open breaker probe.

Keep externally mutating handlers idempotent and use the
[trusted-effect fence](/api/trusted-effects) where applicable. Run a bounded
outage/recovery canary before expanding traffic. See the
[a42 release notes](https://github.com/outlabsio/outlabs-taskq/blob/v0.1.0a42/docs/RELEASE-0.1.0a42.md)
for the complete contract.
