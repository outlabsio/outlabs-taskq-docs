## Tick / reaper

Housekeeping is advisory-lock-deduped maintenance: reap expired leases, fire due database-time schedules, and related cleanup. On the HTTP host, prefer `TaskqRuntime` / `taskq_lifespan` so the facade process owns tick + optional claim-wait listener.

::note
Schedule firing is part of the shipped `0.1.0a19` surface (migration `0010`). Lease reaping remains the core correctness path for stolen/expired attempts.
::

## Wake path

**Polling is correctness. NOTIFY is latency.**

DSN workers may `LISTEN` for early wakeups (`WorkerSettings.listen`, default true). Missed notifications never lose jobs. HTTP workers cannot listen — they poll (optionally with claim-wait long-poll on the facade).

## Soft stop

On SIGTERM: stop claiming → wait `soft_stop_timeout` → hard-cancel handlers → release running work with a shutdown cause.
